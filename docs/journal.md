# Журнал работы

Хронология работы над репозиторием: что сделано, что выяснилось по ходу и что дальше. Новые записи добавляются сверху.

## 2026-11-24: удалённое состояние, реестр образов и деплой

### Сделано

- Состояние Terraform перенесено в бакет Object Storage с версионированием. Ключ доступа к бакету хранится вне репозитория.
- CI после каждого слияния в `main` публикует образ notes-api в GHCR и в Yandex Container Registry, а также копирует туда `postgres:16-alpine`. На pull request публикации нет, только проверки.
- Деплой: при первой загрузке ВМ cloud-init ставит Docker, входит в реестр токеном сервисного аккаунта ВМ и запускает notes-api с PostgreSQL. Пароль базы генерируется на ВМ. Проверено: `/health` отвечает на обеих ВМ сразу после `apply`.
- Права разделены по сервисным аккаунтам: `terraform-sa` управляет инфраструктурой, `ci-pusher` только публикует образы, `vm-puller` только скачивает.

### Что выяснилось по ходу

- Для S3-бэкенда Terraform нужен статический ключ доступа, IAM-токена недостаточно.
- Из зоны `ru-central1-d` не открывались Docker Hub, GHCR и Google, а GitHub и сервисы Yandex открывались. Решение: держать образы в реестре Yandex, рядом с инфраструктурой.
- Yandex Container Registry не принимает служебные вложения buildx (provenance и SBOM). Для этого реестра их нужно отключать.
- Долгоживущие ресурсы (бакет, реестр, сервисные аккаунты) не входят в стек, который удаляется после каждого занятия.

### Дальше

- Блокировка состояния через YDB, модули Terraform, настройка ВМ через Ansible.

## 2026-11-15: Terraform и Yandex Cloud

### Сделано

- Настроен Yandex Cloud CLI и отдельный каталог `portfolio`, чтобы учебные ресурсы не смешивались с проектными.
- Сервисный аккаунт `terraform-sa` с ролью `editor` на каталог. Terraform получает временный IAM-токен (до 12 часов) через `infra/terraform/env.sh`, ключи на диске не хранятся.
- `infra/terraform`: сеть, подсети в зонах `ru-central1-a` и `ru-central1-d`, группа безопасности (SSH и порт 8000), две прерываемые ВМ Ubuntu 24.04, outputs с IP и командами SSH. Версия провайдера закреплена, lock-файл в git.
- Проверено вживую: `plan` → `apply` → SSH на обе ВМ → `destroy`.

### Что выяснилось по ходу

- Провайдер Yandex ставится через зеркало, настроенное в `~/.terraformrc`.
- Квота на количество облачных сетей невелика (`vpc.networks.count`). Пришлось удалить старый учебный стенд с балансировщиком.
- Балансировщик тарифицируется даже при остановленных ВМ, а остановленные ВМ всё равно платят за диски. После занятия всегда `terraform destroy`.
- Без параметра `hostname` имя ВМ внутри совпадает с её ID.
- PR мержится только после того, как отправлены все коммиты. Если PR уже смержен, новые правки идут новым PR.

### Дальше

- Хранение состояния Terraform в Object Storage.
- Публикация образа notes-api в GHCR и деплой на ВМ.

## 2026-11-14 / 15: старт репозитория

### Сделано

- Каркас репозитория: README на двух языках, лицензия MIT, `.gitignore`, `.editorconfig`, `.env.example`, конфигурация pre-commit (gitleaks, yamllint, shellcheck, markdownlint), шаблон pull request, папки `projects/`, `infra/`, `docs/`.
- CI в GitHub Actions: проверки `lint`, `secrets` (gitleaks) и `terraform` (включится, когда появятся файлы `.tf`).
- Защита ветки `main`: изменения только через pull request при зелёных проверках. Проверено на практике: PR #1 (тест защиты), #2 (первый проект), #3 (CI проекта).
- Рабочая среда: виртуальная машина Ubuntu 24.04 в VirtualBox с Docker и Docker Compose, git, pre-commit и SSH-ключом для GitHub. Вся разработка идёт в ней.
- Первый проект `projects/notes-api`: сервис на FastAPI с PostgreSQL, Dockerfile (не от root, с `HEALTHCHECK`), `docker-compose.yml`, тесты, README на двух языках. Проверен вручную: `/health` и запись и чтение заметок работают.
- Workflow `notes-api`: тесты, проверка compose-файла, сборка образа и дымовой тест `/health`.

### Что выяснилось по ходу

- Если хук pre-commit сам исправил файл, коммит отменяется. Нужно снова выполнить `git add` и `git commit`.
- Коммит без реальных изменений не позволяет открыть pull request.
- Файл `.env` лежит рядом с `docker-compose.yml`, а не в корне репозитория. Пароль базы лучше задавать только латиницей и цифрами, потому что он подставляется в адрес подключения.
- PostgreSQL запоминает пароль в томе при первом запуске. Чтобы сменить пароль, нужен `docker compose down -v`.
- Пакет `docker.io` из Ubuntu конфликтует с `containerd.io` из репозитория Docker. Ставится что-то одно.
